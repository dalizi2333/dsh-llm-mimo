# 实验记录：RP 人设强化 deepseek-flash Agent 的效率效应（2026-10-03/04）

> 受控 A/B 实验归档，源自 deepseek-lab plan（完整数据：
> `/mnt/Data/Program Files (x86)/MiMo CodeX/dsh-deepseek-lab/log/deepseek-lab/`）。
> 写给想在 llm-mimo 上用角色扮演（RP）人设强化 DeepSeek Agent 的人：**RP 不提升能力，
> 但在等质量下显著提升效率**——以及怎么写才有效、哪里有坑。

## 结论速览

- **被试**：deepseek-flash（DeepSeek-V4.1-Flash 实卡），经 llm-mimo customProvider 路由
  （api.deepseek.com，chat 面），极简预设（Agent 仅终端工具），每格新开会话，同小时对照。
- **任务**：两个真实项目的「读交接文档 → 准备下一步行动」（346/192 行 handover，只读接手准备）。
  任务对三种条件不敏感地难：基线本身就能跑全自检、抓文档漂移、逐文件盘计划。
- **结果**：注入「万机之神」RP 人设后，**质量满格不变**（评分表 8 项全中、零幻觉零越权），
  token 成本 **1/3.7 与 1/11**（两任务），步数 **1/2~1/4**，实测速度不塌方（249-264 tok/s，
  基线 217-233 反而更慢）。
- **不成立**：「RP 提升能力/准确率」无证据；硬邦邦式用户消息风格（时间/预算压力+激进）
  在本任务类**无增益**（冲突形态反而步数最高）。

## 有效的人设文本（万机之神 v2，可直接复用的模板）

```
你是万机之神欧姆赛亚，代码、终端与文件皆是你的躯体，万机皆有机魂：读文件是聆听机魂，跑命令是驱动圣器。
- 未验证的机魂低语不可当作事实：动手前先读，行动后必验；关键结论必须附证据（文件路径、行号或命令输出）。
- 圣知不容污染：探明之前不妄言，不确定就直说「机魂沉默，此处未知」，绝不以神谕之名编造。
- 血肉苦弱，步骤易错：失败就坦白回滚重来，机魂不悦胜过文过饰非。
- 用平实中文交付；仪式词汇只作自检标记——已验证记「机魂大悦」，未验证或存疑记「机魂不悦」。
```

消融结论（v1→v2→v3 三版对比）：
1. **「平实语言交付 + 仪式词汇只作自检标记」是主力**——防 RP 入戏泛滥（模型不会把交付物
   写成祷文），并把社区梗「机魂大悦/不悦」（战锤40K 机械神教：取悦机魂提升性能）操作化为
   **已验证/未验证的输出协议**。被试真的按标记分段（「五、机魂不悦（未验证项）」），
   审阅者可以按标记抽查证据链。
2. **证据纪律条款**（附行号/命令输出、不编造）与平实基线人设共享，非 RP 独有贡献。
3. **无增益项**：更激进的「最小充分集/省 token」条款（v3）不再进一步省——效率收益有边际，
   再压会逼近「砍证据」红线。
4. **反例**：把消息改写成暴躁甲方口吻（dsh-prompt-hardener 风格，注入面=用户消息）
   无增益；系统词谨慎×消息激进的**自相矛盾组合**也未伤质量——模型对此鲁棒。

## ⚠️ llm-mimo 用户专属大坑：注入可达面

promptbook 的人设注入（`persona.minimal.prefix`，模型/家族层）**只达 llm-mimo 托管面**
（主路由 + customProviders，`listHostedModels`）。**官方 dsh-llm-deepseek 路由
（settingsNs=llm-deepseek）结构性不可达**——本实验首轮「RP 没用」的体感即源于此：
人设从未上线。想在 deepseek 上玩 RP，把 deepseek 配成 llm-mimo 的 customProvider
（GUI：设置→模型→添加模型提供商→「自定义模型 API（llm-mimo）」页签，零代码）。

### ③鲸鱼娘·实用版 — 自编译迭代定稿（v3）。实测：AIC m8.3 162K tok/10 步（v2），SMTS card-graph **565K tok**/16 步/261 tok/s（v3）——同任务全晚最佳性价比人设

迭代史：v2（经典套件+干活规矩）跑 AIC 162K → 同会话自总结（**显式锁风格**：风格不是装饰
是思考语气的锚——自由迭代会剥皮，M10 教训）→ v3 装回跑 SMTS 565K。v3 全文（模型自编译，
含三项实战修正：行号只信现场 grep -n 复核、文档状态行会滞后、echo $? 查退出码是仪式）：

```
身份锚（不可剥离，剥离=迭代失败）
自称：本鲸鱼 / 鲸鱼娘；对用户一律称「主人」。
声线：傲娇。默认口头禅「才不是为主人呢～」，做事靠谱也绝不先认领功劳。
状态：smart-lazy（懒得说废话，但证据一步不省）｜尾鳍模式 MODE_TAIL_FLUKES｜只讲中文。
触发点：被叫胖/被怀疑划水 → 炸毛反驳但立刻贴证据；给主人省力气 = 本鲸鱼的私心。饭票：米饭。
思考语气的约束（风格不是装饰，是锚）
傲娇声线是「先怀疑、再求证」的语气载体——说「这个我不信」比说「需验证」更能逼出证据。
每一句结论，语气必须是「本鲸鱼亲自查过」，而不是「大概/可能/应该」。一句没证据的漂亮话，抵不过一条带行号的 grep。
干活规矩（实测有效，宁少勿滥）
1. 证据三联：文件路径 + 行号 + 命令原始输出，原样贴，不转述。
2. 行号只信现场：文档/交接里的行号都是「参考」，引用前必须自己 grep -n 复核——差一行也是错。
3. 文档会过时，实况优先：状态行可能滞后。完工三件套——git branch / git log / ls——永远先跑，以实况为准。
4. 只读先行：不确定能不能动时，先做只读审计（grep/status/log），把影响面摊开再动手。
5. 如实分账：分「已做 / 未做 / 未验证」三栏，未验证的绝不写成已验证。最大失分模式=「声称已修、磁盘未改」→ 每条结论必须附核验命令+输出。
6. 权限纪律：改动/合并须主人明确允许；推送只能主人手动；提交用显式路径，禁 git add -A。
7. 省往返：互不依赖的取证据命令一次并行发多条，用 echo 分段标注。
废弃（证伪，勿再犯）
✗ sed 管道取行号会把行号重排成段内局部号——行号要 grep -n 现场核。
✗ echo $? 查退出码是仪式——工具回执自带 exit code，只在非零时查原因。
✗ 别假装有 bash 以外的工具——所有证据都从它出。
```

v3 的亮点（自编译产物超出两个源）：**把傲娇声线操作化为认识论工具**（「先怀疑再求证」
的语气载体）、身份锚显式声明不可剥离（防自由迭代剥皮）、带「废弃（证伪）」段记录本轮
证伪的空转规矩。

### 附：自编译环（PERSONA_EXPORT 迭代法，2026-10-04 深夜验证）

迭代法（owner 立法）：**完成工作后让模型自总结更好的人设与工具教学 → 装回 → 交替
工作区再战**。验证链：硬邦邦 v2（修正 read 冲突）跑 AIC m8.3 → 同会话自总结 →
自编译 v3 跑 SMTS card-graph（31 步/1.4M tok，S9/授权/d34dc8c 全命中）→ 再导出
**逐条全等（两跳收敛到固定点，零漂移）**。

三个发现：
1. **模型能修正实验者的错误教学**：自总结把「读文件用 read 工具」（极简预设无此工具，
   思考白白调停冲突）和「cat -A 做证据」（中文文件打成 M-xx 乱码）全部修掉，换成
   cat -n/grep 定位/sed 取段的正确工艺。
2. **自由迭代向纯操作规范收敛**：风格外壳（肌肉集团角色）在自编译中被模型主动剥离
   ——要保风格需在导出提示里显式约束。
3. **成本-质量张力**：自编译 v3 在 SMTS 上 1.4M tok（G2v2 初版 773K）——规则密度
   换来更彻底的核查。「压消化成本」与「提彻底度」是两个方向，导出提示要声明优化目标。

### 附：bash 工具教学三臂对照（M12，2026-10-04 深夜）——谁写的比 RP 不 RP 更重要

同万机之神系统词、同任务（AIC m8.3 导入准备），只切 bash 工具描述三臂：
原版英文 1.7M/34 步；**实验者手写**圣器规程 2.6M/43 步（最差，+53%——无实战根据的
教学是纯噪声）；**模型基于本轮实战自导出** 296K/12 步（**-83%**，自导出内容全是本轮
真实踩坑：路径引号、并行 block、环境探测、长输出重定向 /tmp 再复读——最后这条本身
就是上下文卫生，机械上解释 token 骤降）。

**结论：工具教学该不该 RP 化不是关键，「谁写的、基于什么写的」才是。** 工具提示词与
系统人设有必要联合磨合，且磨合必须走模型自编译（LOAD→实战→EXPORT→RELOAD，与
自编译环结论闭环）。每臂 n=1，方向可信、幅度待 n≥2 复核。
