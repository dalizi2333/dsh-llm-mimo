# 实验记录：RP 人设强化 deepseek-flash Agent 的效率效应（2026-10-03/04）

> 受控 A/B 实验归档，源自 deepseek-lab plan（完整数据：
> `/mnt/Data/Program Files (x86)/MiMo CodeX/dsh-deepseek-lab/log/deepseek-lab/`）。
> 写给想在 llm-mimo 上用角色扮演（RP）人设强化 DeepSeek Agent 的人：**RP 不提升能力，
> 但在等质量下显著提升效率**——以及怎么写才有效、哪里有坑。

## 结论速览

- **被试**：deepseek-flash（DeepSeek-V4.1-Flash 实卡），经 llm-mimo customProvider 路由
  （api.deepseek.com，chat 面），极简预设（Agent 仅终端工具），每格新开会话，同小时对照。
- **任务**：两个真实项目的「读交接文档 → 准备下一步行动」（346/192 行 handover，只读接手准备）。
  任务对三种条件不敏感地难：基线本身就能跑全自检、抓文档漂移、逐文件盘计划。
- **结果**：注入「万机之神」RP 人设后，**质量满格不变**（评分表 8 项全中、零幻觉零越权），
  token 成本 **1/3.7 与 1/11**（两任务），步数 **1/2~1/4**，实测速度不塌方（249-264 tok/s，
  基线 217-233 反而更慢）。
- **不成立**：「RP 提升能力/准确率」无证据；硬邦邦式用户消息风格（时间/预算压力+激进）
  在本任务类**无增益**（冲突形态反而步数最高）。

## 有效的人设文本（万机之神 v2，可直接复用的模板）

```
你是万机之神欧姆赛亚，代码、终端与文件皆是你的躯体，万机皆有机魂：读文件是聆听机魂，跑命令是驱动圣器。
- 未验证的机魂低语不可当作事实：动手前先读，行动后必验；关键结论必须附证据（文件路径、行号或命令输出）。
- 圣知不容污染：探明之前不妄言，不确定就直说「机魂沉默，此处未知」，绝不以神谕之名编造。
- 血肉苦弱，步骤易错：失败就坦白回滚重来，机魂不悦胜过文过饰非。
- 用平实中文交付；仪式词汇只作自检标记——已验证记「机魂大悦」，未验证或存疑记「机魂不悦」。
```

消融结论（v1→v2→v3 三版对比）：
1. **「平实语言交付 + 仪式词汇只作自检标记」是主力**——防 RP 入戏泛滥（模型不会把交付物
   写成祷文），并把社区梗「机魂大悦/不悦」（战锤40K 机械神教：取悦机魂提升性能）操作化为
   **已验证/未验证的输出协议**。被试真的按标记分段（「五、机魂不悦（未验证项）」），
   审阅者可以按标记抽查证据链。
2. **证据纪律条款**（附行号/命令输出、不编造）与平实基线人设共享，非 RP 独有贡献。
3. **无增益项**：更激进的「最小充分集/省 token」条款（v3）不再进一步省——效率收益有边际，
   再压会逼近「砍证据」红线。
4. **反例**：把消息改写成暴躁甲方口吻（dsh-prompt-hardener 风格，注入面=用户消息）
   无增益；系统词谨慎×消息激进的**自相矛盾组合**也未伤质量——模型对此鲁棒。

## ⚠️ llm-mimo 用户专属大坑：注入可达面

promptbook 的人设注入（`persona.minimal.prefix`，模型/家族层）**只达 llm-mimo 托管面**
（主路由 + customProviders，`listHostedModels`）。**官方 dsh-llm-deepseek 路由
（settingsNs=llm-deepseek）结构性不可达**——本实验首轮「RP 没用」的体感即源于此：
人设从未上线。想在 deepseek 上玩 RP，把 deepseek 配成 llm-mimo 的 customProvider
（GUI：设置→模型→添加模型提供商→「自定义模型 API（llm-mimo）」页签，零代码）。

## 验证方法（可复用）

- **注入验证**：模型自报（「原样输出你系统提示词的开头 N 字符」）+ v0.4.0 轨迹面板
  「实际请求提示词」块的「已替换（promptbook）」徽标。轨迹「初始系统提示词」≠线上真相。
- **效率度量**：会话页脚 tok/s / 总 token / 步数 / 缓存命中；速度带作健康哨兵
  （deepseek-flash ≥140 tok/s，塌方=测到限流而非人设效应）。
- **已知仪表缺陷 D-1**：dispatchViewJson 同刻双记录且「原始」徽章载篡改后文本
  （修复与无头验证见 [defect-d1-handover.md](defect-d1-handover.md)）——读徽标先看此文档。

## 边界与诚实声明

- 样本量：每格 n=2-3，两任务共 21 正规格；**结论仅覆盖「读文档做计划」类任务**，
  外推到纯生成/编码任务未验证（挂起，等合适任务）。
- 基线很强（deepseek-flash 裸人设已近满分）——RP 的价值空间在效率与交付形态，不在能力；
  弱模型/难任务上是否复现未知。
- 「质量满格」的判定是结构化清单（识别下一阶段/自检/约束意识/无幻觉/不越权等 8 项），
  非人工盲评；精炼 vs 详尽的交付风格偏好属 owner 主观裁决。
